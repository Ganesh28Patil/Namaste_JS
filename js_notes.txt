What is Garbage Collection in JS ?

Javascript Garbage Collection frees up (clean up) the memmory that is no longer used by program.

----------------------------------------------------------------

Memory leaks & Closure ▶️
    Closures themselves do not inherently cause memory leaks. However, 
    improper use of closures can lead to memory leaks if variables or objects that are no longer needed 
    are kept in memory by the closure, leading to unnecessary memory usage.

    When a closure holds onto large objects or references that are not needed anymore, 
    it can prevent the garbage collector from freeing up that memory.

  Example : 
   function outer() {
        let bigData = new Array(1000000).fill("Some large data");

        return function() {
            console.log('Closure in action');
        };
    }

    const closure = outer(); 
    // Even though 'bigData' is no longer needed, it is still retained in memory by the closure

In Short, A Closure in JS occurs when a function remembers and can access its lexical scope 
(variable in its outer function) even when outer function has finished its execution.

Example : 
function outer() {
    let counter = 0;

    function inner() {
        counter++; // 'counter' is remembered by the closure
        console.log(counter);
    }

    return inner;
}

const increment = outer();
increment(); // 1
increment(); // 2

In this example, even though the outer function has finished execution, 
the inner function retains access to the counter variable. 
This is the core behavior of closures.

// Difference between Parameters & Arguments : -

Parameter: The named variable declared in the function’s definition, e.g., function sample(a, b) {...} — here, a and b are parameters.

Argument: The value provided for a parameter during the function’s invocation, e.g., sample(1, 2) — here, 1 and 2 are arguments.

The short explanation: parameters are in the function definition, arguments are in the function call.

Example Code (with JavaScript syntax)

function sample(a, b) { // a and b are parameters
  console.log(a, b);
}

sample(1, 2); // 1 and 2 are arguments

Comparison Table : 
__________________________________________________________________________________
| Aspect  |	Parameters                       |	Arguments                        |    
|---------|----------------------------------|---------------------------------- | 
| Where   |	 Function definition             |  	Function invocation          |   
| Example |	function foo(x, y)               |	foo(10, 20)                      |
| Role	  |   Placeholder for values         |	Actual values passed             |
| Naming  |	Named in code, labels/variables  |	Can be literals, variables, etc. |

⭐ Asynchronous Function & Event Loop :

JavaScript is a synchronous, single-threaded language.
It has one Call Stack, and it can only do one task at a time.
This Call Stack exists inside the JavaScript Engine, and all JavaScript code is executed there.

Whenever any JavaScript code runs, a Global Execution Context (GEC) is created.
This GEC is then pushed into the Call Stack.
Inside the GEC, the code is executed line by line, in order.

----------- ------------- -------
Suppose we have below code Snippet
function a(){
    console.log("a");
}
a();
console.log("END");
----------- ------------- -------
When the above code is executed, the Global Execution Context (GEC) is created and pushed into the Call Stack. 
JavaScript will then execute the code line by line inside this context.

1) The first line defines the function a(). Since it’s only a declaration, nothing is executed at this point.

2) When the line a(); is encountered, a new Execution Context is created specifically for the function a(). 
   This new context is then pushed onto the Call Stack.

3) Inside the function a(), the statement console.log("a"); is executed, and "a" is printed to the console.

4) Once the function body finishes executing, the execution context for a() is popped off the Call Stack.

5) Now, only the GEC remains in the Call Stack. JavaScript continues to the next line: console.log("END");, which prints "END" to the console.

6) After the last line is executed, the GEC itself is popped off the Call Stack, leaving the Call Stack empty.

This step-by-step process shows how JavaScript executes synchronously, in order, without waiting—just like a train or tide, 
it keeps moving forward without pausing for anything else.

Explaining Event Loop :

Event Loop in Simple Terms

Code Snippet : 
---- ---- ---- ---- ---- ---- --- ---
console.log("Start");

setTimeout(function cb(){
  console.log("Callback");
}, 5000);

console.log("End");

-- --- ---- ---- ---- ---- --- ---- ---

1) When the code starts, a Global Execution Context (GEC) is created inside the Call Stack.

2) Line 1 → console.log("Start") runs.

    The console is a Web API.

    It prints "Start" immediately.

3) Line 2 → setTimeout(...) is called.

    setTimeout is also a Web API.

    It sets a 5-second timer and hands over the callback function cb() to the browser.

    The callback does not enter the Call Stack yet. It just waits until the timer finishes.

4) Line 3 → console.log("End") runs.

    Prints "End" immediately.

5) At this point, the main code is done, so the GEC is popped from the Call Stack.

    But the setTimeout callback is still waiting for its 5000ms timer.

6) After 5 seconds, the Web API moves the callback cb() into the Callback Queue.

7) The Event Loop acts like a gatekeeper.

    It constantly checks: “Is the Call Stack empty?”

    If yes, it takes the callback from the Callback Queue and pushes it into the Call Stack.

9) Finally, the callback cb() gets executed:

    A new Execution Context is created for it.

    Inside it, console.log("Callback") runs.

    "Callback" is printed.

✅ Final Output (in console):

Start
End
Callback   (after 5 sec)

Key Idea (layman style) : 

    i)    Call Stack: Where code runs line by line.

    ii)   Web APIs: Handle async tasks like setTimeout, fetch, etc.

    iii)  Callback Queue: A waiting line for async callbacks.

    iv)   Event Loop: The gatekeeper that checks if the Call Stack is free, and if yes, moves callbacks from the queue into the stack.

👉 This is why JavaScript feels asynchronous, even though it’s single-threaded.
